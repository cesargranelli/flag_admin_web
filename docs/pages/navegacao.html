Padrões de navegação

Como a navegação funciona no admin_web: StatefulShellRoute, push/go, botão voltar e modais.

Estrutura da navegação

O app usa um StatefulShellRoute.indexedStack (definido em lib/src/router/app_router.dart) com uma branch por módulo. O AdminShell é apenas o Scaffold ancestral (para SnackBars/Material); cada branch preserva seu estado (filtros/seletores).

O router usa refreshListenable com o AuthController: qualquer mudança de autenticação reavalia o redirect (login/logout/proteção). Existe também pendingDestination — após autenticar, o usuário volta ao destino que tentava acessar.

context.go vs context.push

context.go — substitui a rota (não empilha)

  • Navegação entre módulos (cards da home, ícone home)
  • Atalhos que trocam de contexto: detalhe do campeonato → Rodadas, detalhe da rodada → Confrontos
  • Ações de salvamento que levam ao detalhe substituindo o form
  • Telas públicas (login, signup, esqueci senha)
  • Back sem pilha nos forms: canPop ? pop : go(rota do módulo)

context.push — empilha (mantém volta)

  • Entrada em detalhes a partir de listagens (tap no card)
  • Formulários de criação que devem permitir voltar à listagem
  • Fluxos com contexto de volta: clube → novo time, campeonato → inscrever times, time → elenco

Botão voltar

Toda tela (exceto a home) exibe um botão voltar no topo (implementado em lib/src/widgets/app_screen.dart): 

// Com histórico (canPop): volta pelo histórico real
if (canPop) → context.pop()

// Sem histórico (listagem vinda da home via go): volta para a home
else → context.go('/')  // "Voltar para Início"

O rótulo do botão indica a página para onde se vai (a anterior): "Voltar para {nome}" — resolvido por backLabel da tela ou pelo nome da rota anterior na pilha. O título da página atual fica centralizado na barra.

Forms com alterações pendentes

Formulários usam PopScope + confirmação "Descartar alterações?" ao sair com mudanças não salvas:

  • OrganizationFormScreen
  • CompetitionCreateScreen / CompetitionEditScreen (via CompetitionFormController.handleBack)

Extras de rota (state.extra)

O state.extra do GoRouter transporta dados entre telas:

  • Detalhes recebem o objeto via extra (fallback ao provider pelo :id)
  • teamAssociate: aceita String (competitionId, antigo) ou record {competitionId, organizationId}
  • gameNew/gameEdit/gameDetail: record GameFormArgs / GameImportArgs
  • teamRoster: competitionId via extra String
